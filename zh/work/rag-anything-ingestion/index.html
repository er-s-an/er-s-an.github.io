减少多模态摄入调用，也不悄悄改变图语义。

在 HKUDS/RAG-Anything PR #453 中，我减少了多模态文档摄入时的模型调用放大，并在维护者评审中补齐 source 解析、删除和失败恢复。最终得到的是明确 opt-in 的效率路径，而不是对默认行为的暗改。

问题是调用放大，不只是延迟

Legacy 多模态摄入会对相关内容重复执行抽取与 embedding 调用。Packed extraction 将符合条件的 modal items 分组，减少调用放大，同时保留 legacy、per-item 和 skip 的明确行为。

公开的合成图像加双表格样例中，legacy 使用 65 次 embedding 和 6 次文本模型调用；packed 分别为 21 次和 4 次，视觉模型均为 1 次。

评审暴露了更深的图生命周期问题

维护者最初复现发现，用于图抽取的 pack ID 无法稳定解析到已注册 source chunks，影响图检索和文档清理；这不是调用次数基准能覆盖的问题。

修订版在抽取前注册 packs，保证公开插入与删除路径中的 source ID 可解析，使用真实 LightRAG stores 覆盖失败批次回退，并保留 legacy 为默认行为。

有完整收据的上游改动

最终 PR 通过 1,283 项测试、Ruff 0.6.4 和 Python 3.10–3.12 CI。Qwen3-VL 与 Qwen embedding 实测覆盖四种模式的插入、查询和公开删除。

维护者从要求修改转为批准，PR 于 2026 年 11 月 12 日合并。文档明确记录 packed 模式的检索候选与 belongs_to 取舍。

基准范围

调用数字来自一个合成功能样例，不是检索质量基准。Packed 为 opt-in；它会省略 belongs_to 关系并增加检索候选，在真实数据上启用前仍需评估。
